TIPS Y TRUCOS
═════════════════════════════════════════════════════════════════════════════

💡 SIN API KEY DE GEMINI:
   → Siempre usa mock (perfecto para testing)
   → No necesitas configurar nada
   → Funciona offline

💡 CON API KEY DE GEMINI:
   → Intenta Gemini primero
   → Si falla (429), cae a mock automáticamente
   → Log: "[EVALUACIÓN MOCK]" = usando fallback

💡 REPRODUCIBILIDAD:
   → Misma lección → Feedback coherente
   → Pero scores varían por dificultad
   → Perfecto para testing

💡 EXTENDER:
   → Más lecciones: edita lib/mock-database.ts
   → Más skills: crea nuevas evaluaciones
   → Custom feedback: modifica mock-evaluations-expanded.ts

¿PREGUNTAS?
═════════════════════════════════════════════════════════════════════════════

P: ¿Necesito Gemini API key?
R: NO. El sistema funciona sin ella. Con key, intenta Gemini primero.

P: ¿Las evaluaciones son siempre iguales?
R: NO. Varían por dificultad. Mismo ID → feedback coherente pero scores varían.

P: ¿Dónde se guardan los resultados?
R: EN MEMORIA. Para persistir, necesitas Supabase (próximo paso).

P: ¿Puedo testear todas las 50 lecciones?
R: SÍ. Todas las 50 están en mock-database.ts. Navega y prueba.

P: ¿Qué hago si Gemini tiene cuota agotada?
R: NADA. El sistema automáticamente usa mock. Sin intervención necesaria.
